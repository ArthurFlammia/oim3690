## Code I want to highlight
```javascript
// Attempt 1: search by dish name
const nameResponse = await fetch(API_BASE + "/search.php?s=" + encodeURIComponent(query));
const nameData = await nameResponse.json();

if (nameData.meals) {
  lastResults = nameData.meals.map(simplify);
} else {
  // Attempt 2: treat the query as an ingredient
  const ingResponse = await fetch(API_BASE + "/filter.php?i=" + encodeURIComponent(query));
  const ingData = await ingResponse.json();
  lastResults = (ingData.meals || []).map(simplify);
}
```
This is the fallback chain inside `searchRecipes()`. TheMealDB has two different
search endpoints and neither one covers what people actually type. `search.php?s=`
matches dish names, `filter.php?i=` matches ingredients, and people type both
without distinguishing.

So I try the name search first. When there's no match, TheMealDB doesn't return an
error — it returns `{"meals": null}` with a 200 status. That means
`if (nameData.meals)` is false and the code falls through to the ingredient search.
One search box handles both cases without the user having to know there were two.

The `(ingData.meals || [])` on the last line is there because the second search can
come back null too. If it does, I map over an empty array instead of crashing on
`null.map()`.

## AI usage this week
Before writing any code I hit TheMealDB's endpoints in the browser to see what they
return — same thing I did on MP3, and it paid off again. Three things came out of
that:

1. `filter.php?i=` only returns `idMeal`, `strMeal`, and `strMealThumb`. No
   instructions, no ingredients. So the detail view can't be built from search
   results — it needs a second call to `lookup.php?i=` once you know which meal the
   user picked. That's a real constraint I found by reading the raw JSON, not
   something I was told.
2. Neither search endpoint alone handles what people actually type, so I chained
   them.
3. When nothing matches, TheMealDB returns `{"meals": null}` with a 200. It's not
   an error, so a `try`/`catch` never fires — the fallback has to be an `if`
   checking whether `meals` is null.

AI wrote a lot of the fetch boilerplate and the render loop. The three findings
above came from testing — specifically #3, which I only found because a search for
something nonsense didn't throw and didn't render either, it just silently did
nothing.

I used `PROPOSAL.md` as the prompt, same as MP3. Giving it the spec I'd already
written produced much closer-to-usable code than describing the app from scratch
would have.

What broke first was the detail view. I tried to render instructions off a
`filter.php` result and got `undefined`, which is what sent me looking at the raw
JSON in the first place.
